## 2. 题意理解（Problem Understanding）

给定一棵二叉树的根结点 `root`，翻转这棵二叉树，并返回其根结点。“翻转”指得到它的**镜像**：每个结点的左右孩子互换，并且这种互换一直进行到所有层。

**示例**

- 输入：`root = [4,2,7,1,3,6,9]`
- 输出：`[4,7,2,9,6,3,1]`

根 4 的左右子树 2、7 互换；2 下面的 1、3 和 7 下面的 6、9 也各自互换。按层看，每一层的结点顺序正好左右颠倒。

- 输入：`root = [2,1,3]`
- 输出：`[2,3,1]`

- 输入：`root = []`
- 输出：`[]`

**关键要求**

1. 输入约束：结点数在 $`[0, 100]`$ 内，$`-100 \le \mathrm{Node.val} \le 100`$。结点值与算法无关，只用于检查结果。
2. 翻转必须作用到**每一个**结点，而不只是根：只交换根的两个孩子，第二层以下仍保持原来的左右顺序。
3. 边界：空树返回空树；只有一个孩子的结点，翻转后那个孩子换到另一侧；树可能退化成一条链。

## 4. 算法表达（Algorithm Specification）

**算法名称：** 递归深度优先搜索（Recursive Depth-First Search），先翻转两棵子树，再在根结点交换

### 4.1 输入（Input）

一棵二叉树 $`T`$，按递归方式定义：$`T`$ 要么是空树 $`\varnothing`$，要么是三元组 $`(r, L, R)`$，其中 $`r`$ 是根结点，$`L`$、$`R`$ 分别是左、右子树（也是二叉树）。

记 $`\lvert T \rvert`$ 为 $`T`$ 的结点数，满足：

- $`0 \le \lvert T \rvert \le 100`$；
- 每个结点只有一个父结点（根除外），沿孩子指针走不会回到已经经过的结点，即输入确实是一棵树。

非空树 $`(r, L, R)`$ 中，$`L`$、$`R`$ 互不相交且都不含 $`r`$，$`\lvert T \rvert = 1 + \lvert L \rvert + \lvert R \rvert`$。

### 4.2 输出（Output）

定义 $`T`$ 的**镜像** $`M(T)`$：

```math
M(T) =
\begin{cases}
\varnothing, & T = \varnothing \\
(r,\ M(R),\ M(L)), & T = (r, L, R)
\end{cases}
```

输出 $`M(T)`$ 的根结点（空树时为 `nil`）。实现直接改写输入结点的 `Left`、`Right` 指针，返回后输入树本身就变成了 $`M(T)`$，所用结点与输入完全相同。

### 4.3 伪代码（Pseudocode）

```text
INVERT-TREE(x)                        ▷ x 是子树的根，可能为 NIL
    if x == NIL
        return NIL
    newLeft  = INVERT-TREE(x.right)
    newRight = INVERT-TREE(x.left)
    x.left  = newLeft
    x.right = newRight
    return x
```

算法直接返回 `x`，没有结果变量。Go 代码用一条多重赋值 `root.Left, root.Right = invertTree(root.Right), invertTree(root.Left)` 完成第 4～7 行：Go 规范规定多重赋值先按顺序求出右侧所有表达式，再统一赋值，所以两次递归调用都读到的是**原来的** `Right` 和 `Left`，与伪代码先存入 `newLeft`、`newRight` 再赋值等价。

**状态定义**

- `x`：当前子树的根；`x == NIL` 表示空子树。
- 返回值：`x` 本身（空树时为 NIL）；返回时以 `x` 为根的子树已经被改写成原子树的镜像。

### 4.4 正确性（Correctness）

**证明方法：对结点数的强归纳（结构归纳）**

#### 一、正确性依赖的关键条件

1. **输入是一棵树**（题目条件）：$`L`$、$`R`$ 互不相交且都不含 $`r`$，所以 $`\lvert L \rvert, \lvert R \rvert < \lvert T \rvert`$。这保证了递归规模严格变小，从而一定终止，也是归纳能进行的前提。
2. **调用只改写自己子树内的指针**（待证，并入定理一起归纳）：`INVERT-TREE(x)` 只修改以 `x` 为根的子树中结点的 `left`、`right` 字段，不碰子树外的任何结点。
3. **两次递归调用读取的是原指针**（由伪代码第 4、5 行的顺序，或 Go 多重赋值的求值规则保证）：第 5 行调用前，`x.left` 还没有被改写。

#### 二、正确性证明

**定理。** 对任意满足 4.1 条件的二叉树 $`T`$，`INVERT-TREE(T)` 终止；它只修改 $`T`$ 中结点的孩子指针；返回时，返回值所指的结构恰好是 $`M(T)`$，并且所用结点集合与 $`T`$ 相同。

*证明*：对 $`n = \lvert T \rvert`$ 做强归纳。

**基础（$`n = 0`$）**：$`T = \varnothing`$，`x == NIL` 成立，返回 NIL，等于 $`M(\varnothing) = \varnothing`$，没有修改任何指针。

**归纳步（$`n \ge 1`$）**：假设对所有结点数小于 $`n`$ 的树结论成立。$`T = (r, L, R)`$ 非空，跳过基础分支。

- **第 4 行**：$`\lvert R \rvert < n`$，由归纳假设，`INVERT-TREE(x.right)` 终止，只改写 $`R`$ 内的指针，并返回 $`M(R)`$ 的根，存入 `newLeft`。由于 $`L`$ 与 $`R`$ 不相交、$`r \notin R`$，这一步不影响 $`L`$ 的结构，也不影响 `x.left` 与 `x.right` 的值。
- **第 5 行**：此时 `x.left` 仍指向原来的 $`L`$（关键条件 3），且 $`L`$ 的结构未变。同理得到 $`M(L)`$ 的根，存入 `newRight`，这一步也不影响已经得到的 $`M(R)`$（它由 $`R`$ 的结点组成，与 $`L`$ 不相交）。
- **第 6、7 行**：只改写 $`r`$ 自己的两个指针，于是以 $`r`$ 为根的结构是 $`(r, M(R), M(L)) = M(T)`$。

整个调用修改的指针都在 $`\{r\} \cup L \cup R`$ 中，所用结点仍是 $`T`$ 的结点。∎

两次递归调用的先后顺序可以互换：它们作用在不相交的子树上，互不读取对方的结点。真正不能做的，是在第 5 行之前就改写 `x.left`（见难点一）。

**推论（镜像是对合）。** 对任意二叉树 $`T`$，$`M(M(T)) = T`$。对结点数归纳：$`M(M(\varnothing)) = \varnothing`$；非空时 $`M(M((r, L, R))) = M((r, M(R), M(L))) = (r, M(M(L)), M(M(R))) = (r, L, R)`$。测试 `TestInvertTreeTwice` 检查的就是这一点。

**推论（中序序列反转）。** 记 $`\mathrm{In}(T)`$ 为 $`T`$ 的中序遍历序列，则 $`\mathrm{In}(M(T))`$ 是 $`\mathrm{In}(T)`$ 的逆序。归纳：空树显然；非空时 $`\mathrm{In}(M(T)) = \mathrm{In}(M(R)) \cdot r \cdot \mathrm{In}(M(L))`$，由归纳假设等于 $`\mathrm{rev}(\mathrm{In}(R)) \cdot r \cdot \mathrm{rev}(\mathrm{In}(L)) = \mathrm{rev}(\mathrm{In}(L) \cdot r \cdot \mathrm{In}(R))`$。因此翻转一棵二叉搜索树，得到的是按关键字**从大到小**做中序遍历的树。

#### 三、结论

空树的镜像是空树；非空树的镜像由定义归结为两棵更小子树的镜像，归纳假设保证这两步各自正确且互不干扰，最后在根结点交换两个指针即可。因此算法对所有合法输入原地得到输入树的镜像，并返回原来的根结点。

### 4.5 复杂度分析（Complexity Analysis）

设 $`n = \lvert T \rvert`$，$`h`$ 为树的最大深度（按结点数计，空树为 0）。

**时间复杂度：$`\Theta(n)`$**

数一数调用次数。每个结点恰好作为一次非空调用的参数：根由外部调用，其余结点由它唯一的父结点调用。空调用的次数等于空孩子指针的个数：$`n \ge 1`$ 时共有 $`2n`$ 个孩子指针，其中 $`n - 1`$ 个指向结点，剩下 $`n + 1`$ 个为空；$`n = 0`$ 时只有一次空调用。所以调用总数是

```math
n + (n + 1) = 2n + 1
```

每次调用除递归外只做常数次操作，总时间为 $`\Theta(n)`$。任何正确算法都必须改写每个至少有一个孩子的结点的指针，而且在读到某个结点之前无法知道它有没有孩子，所以必须访问全部 $`n`$ 个结点，$`\Omega(n)`$ 不可避免。

**空间复杂度：$`\Theta(h)`$**

算法不分配任何新结点，结果就是改写后的输入树，不计入额外空间。额外空间全部来自递归栈，最大深度是 $`h + 1`$（走到最深的叶子后再调用一次空孩子；$`n = 0`$ 时为 1），即 $`\Theta(h)`$。

- **最坏情况**：树退化成一条链，$`h = n`$，栈深度为 $`\Theta(n)`$。测试 `TestInvertTreeChain` 用的就是 100 个结点的左链和右链。
- **最好情况**：完全二叉树，$`h = \lfloor \log_2 n \rfloor + 1`$，栈深度为 $`\Theta(\log n)`$。

## 5. 思维难点（Learning Notes）

### 难点一：交换能不能拆成两条赋值语句？

很自然的写法是

```go
root.Left = invertTree(root.Right)
root.Right = invertTree(root.Left) // 错误
```

**理解过程**

第二行读到的 `root.Left` 已经被第一行改写，指向的是**已经翻转过的原右子树**。于是第二行把原右子树又翻转了一次（变回原样），原左子树则被整个丢掉，最后 `Left` 和 `Right` 指向同一棵子树。结果不再是一棵树，而且原左子树的结点全部丢失。

这个错误还会让时间变成指数级：沿着一条右链，每一层都对同一棵子树递归两次，100 层的右链需要约 $`2^{100}`$ 次调用。测试里给链状用例加超时，就是为了让这种错误表现为失败而不是卡住。

正确的做法是保证两次递归都读到原来的指针：要么像伪代码那样先存进临时变量，要么用 Go 的多重赋值（右侧全部求值后再赋值），要么先交换再递归（见难点二）。

**可迁移思维：** 原地修改指针时，先问“这条语句读到的字段，是不是前面刚被改写过”。交换两个字段的标准写法是先读后写，Go 里就是一条多重赋值。

### 难点二：先序还是后序？

**理解过程**

本实现是后序：两棵子树都翻转完，再在根结点交换。先序同样正确：先交换 `x.left` 与 `x.right`，再分别递归翻转两个新孩子。两种写法都满足“每个结点恰好交换一次”，而结点 $`v`$ 最终的位置只取决于它到根的路径上每个祖先（以及它自己）是否都交换过，与交换的先后无关。中序则不行：先递归左子树，交换，再递归“右子树”时，右指针已经指向刚翻转过的原左子树，会把它翻回去，原右子树则从未被处理。

同样的道理，用栈或队列逐个取出结点、对每个结点交换左右孩子，也是正确的非递归写法，见[显式栈 DFS](../iterative-dfs/summary.zh-CN.md)；换成队列就是层序，额外空间是最宽一层的结点数，而不是树高。

**可迁移思维：** 当对每个结点做的操作只是“局部交换”，并且结果与操作顺序无关时，先序、后序、层序都可以；但必须保证每个结点恰好被处理一次。中序把同一个结点的两次子树访问分在交换两侧，最容易出错。

### 难点三：路径视角下的镜像

**理解过程**

把从根到某个结点的路径记成由 L、R 组成的字符串。由 $`M`$ 的定义归纳可知：原树中路径为 $`s`$ 的结点，在镜像中路径为把 $`s`$ 中每个 L 换成 R、每个 R 换成 L 得到的串。因此镜像不改变任何结点的深度，层序输出时每一层的顺序正好反过来（示例 1 的第三层 `1,3,6,9` 变成 `9,6,3,1`），中序序列整体反转（4.4 的推论）。

这也解释了二叉树为什么要区分左右孩子：CLRS 附录 B.5.3 强调，二叉树里“只有左孩子”和“只有右孩子”是两棵不同的树，镜像变换正是在交换这种位置信息。

**可迁移思维：** 判断两棵树是否互为镜像、一棵树是否对称时，可以把问题翻译成“对应路径上的结点相同，路径的 L/R 互换”，然后写出同时递归两棵树的比较。

## 6. 可迁移知识（Key Takeaways）

本题总结出以下可复用的方法：

1. **Recursive Definition to Recursive Code（按递归定义直接写递归）**：在本题中，先写出 $`M(T)`$ 的递归定义，代码与定义逐行对应。适用于镜像、复制、序列化等“对整棵树做结构变换”的问题。条件是变换在根结点处只依赖两棵子树的变换结果。
2. **Structural Induction with Disjoint Subtrees（利用子树不相交的结构归纳）**：在本题中，归纳时额外证明“一次调用只修改自己子树内的指针”，从而两次递归互不干扰。适用于证明任何原地修改树的递归算法。前提是输入确实是一棵树，子树之间没有共享结点。
3. **Read Before Write When Swapping（交换时先读后写）**：在本题中，两次递归必须都读到原来的 `Left`、`Right`。适用于所有原地交换字段或指针的场景（链表反转、数组交换）。Go 的多重赋值天然满足先读后写，拆成两条语句则可能读到已改写的值。
4. **Order-Independent Local Updates（与顺序无关的局部更新）**：在本题中，每个结点交换一次即可，先序、后序、层序都正确，中序不行。适用于判断一种逐结点操作能否换用迭代或层序实现。限制：操作结果依赖子树已处理完（如求高度）时只能用后序。

**一句话总结**

镜像满足“空树的镜像是空树，非空树的镜像是根不变、左右子树互换并各自取镜像”，按定义递归即可；两棵子树不相交保证两次递归互不干扰，而交换时必须先读后写，否则会把同一棵子树翻转两次并丢掉另一棵。
