## 2. 题意理解（Problem Understanding）

给定一棵二叉树的根结点 `root`，翻转这棵二叉树（得到它的镜像：每个结点的左右孩子互换，直到所有层），并返回其根结点。

**示例**

- 输入：`root = [4,2,7,1,3,6,9]`，输出：`[4,7,2,9,6,3,1]`
- 输入：`root = [2,1,3]`，输出：`[2,3,1]`
- 输入：`root = []`，输出：`[]`

**关键要求**

1. 输入约束：结点数在 $`[0, 100]`$ 内，$`-100 \le \mathrm{Node.val} \le 100`$。
2. 翻转必须作用到每一个结点，而不只是根。
3. 边界：空树；只有一个孩子的结点；退化成链的树。

## 4. 算法表达（Algorithm Specification）

**算法名称：** 显式栈深度优先搜索（Explicit-Stack Depth-First Search），弹出时交换

### 4.1 输入（Input）

一棵二叉树 $`T`$：要么是空树 $`\varnothing`$，要么是 $`(r, L, R)`$，其中 $`L`$、$`R`$ 是互不相交、都不含 $`r`$ 的左右子树。$`0 \le \lvert T \rvert \le 100`$，且输入确实是一棵树（每个非根结点恰有一个父结点）。

### 4.2 输出（Output）

$`T`$ 的镜像 $`M(T)`$ 的根结点，其中

```math
M(T) =
\begin{cases}
\varnothing, & T = \varnothing \\
(r,\ M(R),\ M(L)), & T = (r, L, R)
\end{cases}
```

实现原地改写输入结点的指针，返回原来的根。

### 4.3 伪代码（Pseudocode）

栈用 0-based 切片表示，栈顶是最后一个元素。

```text
INVERT-TREE(root)
    if root == NIL
        return NIL
    S = 只含 root 的栈
    while S 非空
        x = POP(S)
        if x.left ≠ NIL
            PUSH(S, x.left)
        if x.right ≠ NIL
            PUSH(S, x.right)
        交换 x.left 与 x.right
    return root
```

算法直接返回 `root`，没有结果变量。代码与伪代码逐行对应：`stack[len(stack)-1]` 加截断是 POP，`append` 是 PUSH，`node.Left, node.Right = node.Right, node.Left` 是交换。

代码中的 `stack[0] = root` 是多余的：切片字面量 `[]*TreeNode{root}` 已经把 `root` 放在下标 0，这一行再写一次同样的值，删掉后行为完全相同（测试中删去这一行，全部用例照样通过）。开头的 `root == nil` 判断则不能省：否则栈里会放进一个 `nil`，弹出后读 `node.Left` 会空指针 panic。

**状态定义**

- `stack`：已经发现、但还没有交换过的结点。
- `node`：本轮弹出、正在处理的结点。

### 4.4 正确性（Correctness）

**证明方法：循环不变式 + 交换顺序无关引理**

#### 一、正确性依赖的关键条件

1. **输入是一棵树**（题目条件）：每个非根结点只有一个父结点，所以它只会在父结点被处理时入栈一次。
2. **交换只改动当前结点自己的两个字段**（由代码）：处理 `x` 不会改变任何其他结点的指针，也不改变 `x` 的孩子**集合**，只改变左右位置。
3. **引理 1（交换顺序无关）**：若 $`T`$ 的每个结点都恰好交换一次左右指针，不论顺序如何，最终结构都是 $`M(T)`$。

**引理 1 的证明。** 由关键条件 2，结点 $`v`$ 的两个字段只在处理 $`v`$ 那一次被改动，所以最终 $`v`$ 的左指针是它原来的右孩子，右指针是它原来的左孩子，与其他结点何时处理无关。再对结点数归纳证明“每个结点都换过的树就是 $`M(T)`$”：空树显然；非空时根 $`r`$ 的左指针指向原 $`R`$ 的根，而 $`R`$ 中每个结点也都换过，由归纳假设这棵子树是 $`M(R)`$；右侧同理是 $`M(L)`$。所以整体是 $`(r, M(R), M(L)) = M(T)`$。∎

#### 二、循环不变式

下面的“孩子”“后代”都按**原树** $`T`$ 说；由关键条件 2，交换不改变孩子集合，所以这些关系在算法执行中不变。设 $`n \ge 1`$（$`n = 0`$ 时第 1 行直接返回 NIL $`= M(\varnothing)`$）。每次检查 `while` 条件时，把结点分成三类：

- $`P`$：已处理，即已弹出并且恰好交换过一次；
- $`S`$：在栈中，每个恰好出现一次，尚未交换；
- $`U`$：未触及，尚未交换，也不在栈中。

**不变式**：$`P`$、$`S`$、$`U`$ 互不相交且覆盖全部结点；$`U`$ 恰好是 $`S`$ 中各结点的**真后代**之并。

**初始化**：$`S = \{r\}`$，$`P = \varnothing`$，$`U`$ 是其余所有结点，即 $`r`$ 的全部真后代。成立。

**保持**：弹出 $`x \in S`$。$`x`$ 尚未交换，所以此时读到的 `x.left`、`x.right` 正是原来的孩子。它们是 $`x`$ 的真后代，由不变式在 $`U`$ 中；又因为不同栈中结点的子树互不相交（每个结点只有一个父结点），它们不属于其他栈中结点的子树。把非空孩子压栈，它们从 $`U`$ 移到 $`S`$，各出现一次；然后交换 $`x`$，$`x`$ 移到 $`P`$。新的 $`U`$ 是原 $`U`$ 去掉 $`x`$ 的孩子：$`x`$ 的真后代去掉 $`x`$ 的孩子，正好是这些孩子的真后代之并；其他栈中结点的部分不变。不变式保持。

**终止**：每轮恰好有一个结点从 $`S`$ 移进 $`P`$，并且不会再离开，所以循环恰好执行 $`n`$ 轮后停止。此时 $`S = \varnothing`$，由不变式 $`U = \varnothing`$，于是 $`P`$ 是全部结点，每个结点恰好交换过一次。由引理 1，结构是 $`M(T)`$，返回的 `root` 就是 $`M(T)`$ 的根。∎

#### 三、结论

栈保证每个结点恰好被发现一次、处理一次，引理 1 保证处理顺序无关紧要，所以算法对所有合法输入原地得到镜像。这也说明“先交换再压栈”同样正确：压进去的孩子集合不变，只是先后不同（测试中做过这个改动，全部通过）。

### 4.5 复杂度分析（Complexity Analysis）

设 $`n = \lvert T \rvert`$，$`h`$ 为树的最大深度（按结点数计）。

**时间复杂度：$`\Theta(n)`$**

由 4.4，循环恰好 $`n`$ 轮。每轮一次弹栈、至多两次压栈、一次交换。`append` 在容量不足时按倍数扩容，总复制量是 $`O(n)`$，摊还到每次压栈为 $`O(1)`$。总时间 $`\Theta(n)`$。

**空间复杂度：$`O(h)`$，最坏 $`\Theta(n)`$**

记结点的深度为根到它的边数，根为 0。**断言**：每次检查 `while` 条件时，栈中结点从栈底到栈顶的深度不减；比栈顶深度小的每个深度至多出现一次；栈顶深度至多出现两次。

- 初始只有根，成立。
- 弹出栈顶 $`x`$（深度 $`k`$）后，剩下结点的深度都 $`\le k`$，且深度 $`k`$ 至多还剩一个。再压入的孩子深度都是 $`k + 1`$，严格大于剩下的所有深度，至多两个。断言保持。

不同深度至多有 $`h`$ 种，只有栈顶那种可能出现两次，所以栈中至多 $`h + 1`$ 个结点。切片截断不释放底层数组，但容量至多是历史最大长度的常数倍，仍为 $`O(h)`$。

- **链状树**：每轮弹出一个、压入一个，栈中始终只有 1 个结点，额外空间 $`O(1)`$。这一点比递归解法好：递归在链上要 $`\Theta(n)`$ 层调用栈。
- **最坏情况**：沿右侧往下的主干上每个结点都另有一个左叶子。每轮先压左叶子、再压右侧主干结点，弹出的总是主干结点，左叶子在栈中越积越多，栈大小约为 $`h \approx n/2`$，即 $`\Theta(n)`$。

## 5. 思维难点（Learning Notes）

### 难点一：为什么可以不按递归的顺序做？

递归版的结构是“先翻转子树，再在根交换”，看上去依赖顺序。

**理解过程**

把镜像拆到单个结点上看：最终每个结点的左指针都是原来的右孩子、右指针都是原来的左孩子（引理 1）。每次交换只动自己的两个字段，不同结点的交换互不影响，所以只要保证“每个结点恰好交换一次”，用栈、队列还是递归，先序还是后序，都能得到同一结果。栈在这里只负责“不重不漏地访问每个结点”。

反过来，同一个结点交换两次就等于没交换。这就是测试里“左孩子压栈两次”会失败的原因，也是递归版难点一里顺序赋值错误的本质：某棵子树被处理了两次。

**可迁移思维：** 当逐结点操作互不干扰、而且每个结点只需做一次时，遍历顺序可以任意选；正确性的关键就变成“不重不漏”，用不变式证明即可。

### 难点二：读孩子在交换之前还是之后？

**理解过程**

本实现先读 `node.Left`、`node.Right` 压栈，再交换。反过来先交换、再把（已经换位的）两个孩子压栈也对：两个孩子都会入栈，集合不变，只是出栈顺序变了。真正需要注意的只有一点：两个孩子都要压，不能因为交换后位置变了就漏掉一个。

另一个细节是出栈顺序：先压左、后压右，所以右子树先被处理。由于每个结点在出栈时才交换，结点的处理顺序“根、原右子树、原左子树”正好是**翻转后那棵树**的先序。

**可迁移思维：** 用显式栈模拟遍历时，压栈顺序决定访问顺序，但只要每个结点都入栈一次，结果与顺序无关的操作就不受影响；需要特定输出顺序（如先序序列）时，才要按“先右后左”压栈。

### 难点三：显式栈的空间比递归好在哪里？

**理解过程**

递归版的调用栈深度就是当前路径长度，链状树上是 $`\Theta(n)`$。本实现的栈里放的是“已发现、待处理”的结点，弹出一个才压入它的孩子，链状树上始终只有 1 个。4.5 的断言说明栈里至多 $`h + 1`$ 个结点，最坏仍是 $`\Theta(n)`$，但出现在“每层都留下一个待处理兄弟”的树上，而不是链上。

本题 $`n \le 100`$，两种写法都不会有栈溢出问题。显式栈的价值在于：结点数很大、树又可能很深时，不受调用栈大小限制。

**可迁移思维：** 估计显式栈的空间时，要看“栈里同时有多少待处理结点”，而不是直接照搬递归的 $`O(h)`$；两者的最坏情况可能出现在不同形状的树上。

## 6. 可迁移知识（Key Takeaways）

本题总结出以下可复用的方法：

1. **Explicit Stack Replacing Recursion（用显式栈代替递归）**：在本题中，栈保存“已发现、未处理”的结点，每轮弹出一个、压入它的孩子。适用于树和图的深度优先遍历、需要避免深递归的场景。条件是对结点的处理不依赖“子树已经处理完”；需要后序结果（如求高度）时，要额外记录状态。
2. **Discovered / Processed Invariant（已发现 / 已处理不变式）**：在本题中，用 $`P`$、$`S`$、$`U`$ 三类结点和“$`U`$ 是 $`S`$ 的真后代”证明不重不漏。适用于证明各种基于栈或队列的遍历（DFS、BFS）恰好访问每个结点一次。前提是图是树，或者另有 visited 标记防止重复入栈。
3. **Order-Independent Local Updates（与顺序无关的局部更新）**：在本题中，引理 1 说明每个结点交换一次即可，与顺序无关。适用于判断一种逐结点操作能否换用任意遍历顺序。限制：每个结点必须恰好处理一次，交换这类操作做两次会抵消。
4. **Stack Size Bound by Depth Profile（按深度分布界定栈大小）**：在本题中，栈中深度不减、只有栈顶深度可重复，所以至多 $`h + 1`$ 个结点。适用于分析“弹出一个、压入其孩子”的 DFS 的空间。注意最坏情况不是链，而是每层留下待处理兄弟的树。

- [3619. 总价值可以被 K 整除的岛屿数目（显式栈 DFS）](../../../../Algorithms/graph-search/3619-count-islands-with-total-value-divisible-by-k/iterative-dfs/summary.zh-CN.md) — 网格图上的显式栈 DFS；图中结点可能被多个邻居发现，所以需要 visited 标记，而本题输入是树，每个结点只会被父结点压栈一次。
- [226. 翻转二叉树（递归 DFS）](../recursive-dfs/summary.zh-CN.md) — 同一题的递归写法，按镜像的递归定义做结构归纳；可对照两种写法在链状树上的空间差异。

---

**一句话总结**

镜像等于“每个结点各交换一次左右指针”，而且与交换顺序无关，所以用栈不重不漏地取出每个结点并交换即可；正确性由“已处理 / 在栈中 / 未触及”的不变式保证，栈里至多 $`h + 1`$ 个结点，在链状树上只有 1 个。
