## 2. 题意理解（Problem Understanding）

题意、示例与关键要求见[排序键解法 §2](../sorted-key/summary.zh-CN.md#2-题意理解problem-understanding)。本解法额外依赖一条约束：`strs[i]` 只含小写英文字母，所以字母表 $`\Sigma`$ 只有 26 个字母，可以用长度为 26 的数组按 `s[i]-'a'` 计数。

## 4. 算法表达（Algorithm Specification）

**算法名称：** 计数键分组（Count-Key Grouping）

### 4.1 输入（Input）

与[排序键解法 §4.1](../sorted-key/summary.zh-CN.md#41-输入input)相同：$`S = \langle s_0, \ldots, s_{n-1} \rangle`$，每个 $`s_i`$ 是 $`\Sigma = \{\mathtt{a}, \ldots, \mathtt{z}\}`$ 上长度不超过 100 的字符串。把字母 $`c`$ 编号为 $`\mathrm{idx}(c) = c - \mathtt{a} \in \{0, \ldots, 25\}`$。

### 4.2 输出（Output）

与[排序键解法 §4.2](../sorted-key/summary.zh-CN.md#42-输出output)相同：输出恰好是“互为字母异位词”这一等价关系的全部等价类。

### 4.3 伪代码（Pseudocode）

伪代码下标从 0 开始。

```text
GROUP-ANAGRAMS-COUNT-KEY(S)
    T ← empty hash table            // 计数向量 → 字符串列表
    for i ← 0 to n - 1
        cnt[0..25] ← all 0
        for j ← 0 to |s_i| - 1
            cnt[s_i[j] - 'a'] ← cnt[s_i[j] - 'a'] + 1
        if cnt ∉ T
            T[cnt] ← empty list
        APPEND(T[cnt], s_i)

    res ← empty list
    for each key in T
        APPEND(res, T[key])
    return res
```

**状态定义**

- `T`：对应代码中的 `groups`，类型是 `map[[26]int][]string`，把计数向量映射到这个键下的字符串列表。
- `cnt`：对应代码中的 `cnt`，类型是 `[26]int`，`cnt[c - 'a']` 是字母 $`c`$ 在当前字符串中的出现次数。每轮外层循环用 `var cnt [26]int` 重新声明，自动清零。
- `res`：所有组组成的列表。

Go 的数组是值类型且可比较，`groups[cnt]` 会把当前 26 个计数复制一份作为键，之后下一轮的 `cnt` 与表里的键互不影响。与排序键解法一样，代码借助“读不存在的键返回 `nil`”省掉了显式的 `if cnt ∉ T` 分支。

### 4.4 正确性（Correctness）

**证明方法：计数循环不变式 + 引用排序键解法的引理 0 与引理 2**

#### 一、正确性依赖的关键条件

1. **字母异位词等价于计数相同**（[排序键解法引理 0](../sorted-key/summary.zh-CN.md#二正确性证明)）：$`s \sim t \iff \mathrm{cnt}_s = \mathrm{cnt}_t`$。
2. **计数循环算出的就是 $`\mathrm{cnt}_s`$**（引理 3，本文证明）。
3. **按完全不变量分组得到全部等价类**（[排序键解法引理 2](../sorted-key/summary.zh-CN.md#二正确性证明)）：只要键函数 $`f`$ 满足 $`f(s) = f(t) \iff s \sim t`$。
4. **输入只含小写字母**（题目给定）：保证下标 `s[i]-'a'` 落在 $`[0, 25]`$ 内。

#### 二、正确性证明

**引理 3（计数循环）**：对字符串 $`s`$，内层循环结束时，对每个字母 $`c`$ 有 $`\mathrm{cnt}[\mathrm{idx}(c)] = \mathrm{cnt}_s(c)`$。

**循环不变式**

在内层循环每次迭代开始时（已处理 $`s[0..j-1]`$）：

**不变式：前缀计数**

对每个字母 $`c`$，$`\mathrm{cnt}[\mathrm{idx}(c)]`$ 等于 $`c`$ 在前缀 $`s[0..j-1]`$ 中的出现次数。

**初始化（Initialization）**

$`j = 0`$，前缀为空，所有计数为 0，与 `cnt` 清零后的状态一致。

**保持（Maintenance）**

假设处理 $`s[j]`$ 之前不变式成立，记 $`c' = s[j]`$。

- **字母 $`c'`$**：前缀从 $`s[0..j-1]`$ 变成 $`s[0..j]`$ 后，$`c'`$ 的出现次数加 1；算法恰好执行 $`\mathrm{cnt}[\mathrm{idx}(c')] \leftarrow \mathrm{cnt}[\mathrm{idx}(c')] + 1`$。由条件 4，$`\mathrm{idx}(c') \in [0, 25]`$，下标合法。
- **其他字母 $`c \ne c'`$**：出现次数不变，$`\mathrm{idx}`$ 是单射，所以 $`\mathrm{cnt}[\mathrm{idx}(c)]`$ 不被修改，仍然正确。

**终止（Termination）**

循环在 $`j = |s|`$ 时结束，前缀就是整个 $`s`$，不变式给出 $`\mathrm{cnt}[\mathrm{idx}(c)] = \mathrm{cnt}_s(c)`$。

**计数键是完全不变量**：记 $`f(s)`$ 为引理 3 算出的数组。由引理 3，$`f(s) = f(t)`$ 当且仅当对所有 $`c`$ 有 $`\mathrm{cnt}_s(c) = \mathrm{cnt}_t(c)`$，即 $`\mathrm{cnt}_s = \mathrm{cnt}_t`$；再由引理 0，这当且仅当 $`s \sim t`$。Go 判断两个 `[26]int` 相等就是逐个比较 26 个分量，与这里的相等含义一致。

**分组**：外层循环与排序键解法结构相同，只是键换成 $`f`$。$`f`$ 满足引理 2 的条件，所以引理 2 的循环不变式与结论原样成立：输出恰好是全部等价类，组内保持输入顺序。

#### 三、结论

计数数组正是判定字母异位词的量本身，所以它既不会拆散同一组，也不会合并不同组；按它分组得到的就是题目要求的全部等价类。组的先后由 `map` 的随机遍历顺序决定，题目允许任意顺序。

### 4.5 复杂度分析（Complexity Analysis）

记号同[排序键解法 §4.5](../sorted-key/summary.zh-CN.md#45-复杂度分析complexity-analysis)：$`n`$ 个字符串，总长度 $`L = \sum_i \ell_i`$，最大长度 $`k`$，组数 $`g \le n`$；另记字母表大小 $`|\Sigma| = 26`$。

**时间复杂度：期望 O(L + n|Σ|)**

处理字符串 $`s_i`$ 的各步：

- 清零 `cnt`：$`O(|\Sigma|)`$。
- 计数循环：$`\ell_i`$ 次，每次 $`O(1)`$，$`O(\ell_i)`$。
- 查表与追加：键是 26 个整数，计算散列值和比较键都是 $`O(|\Sigma|)`$；期望 $`O(1)`$ 次比较，`append` 摊还 $`O(1)`$。合计期望 $`O(|\Sigma|)`$。

第二个循环 $`O(g)`$。总计期望

```math
O\Bigl(\sum_i \bigl(\ell_i + |\Sigma|\bigr) + g\Bigr) = O(L + n|\Sigma|)
```

本题 $`|\Sigma| = 26`$ 是常数，即期望 $`O(n + L)`$，与读入全部输入同阶。与排序键解法的 $`O(n + \sum_i \ell_i \log \ell_i)`$ 相比，省掉了排序的对数因子；但当字符串很短（例如 $`\ell_i < 26`$）时，每个字符串固定付出的 $`|\Sigma|`$ 可能比排序还大，两者在本题范围内的实际快慢要靠测量，不能只看渐近式。

**空间复杂度：O(n|Σ|)**

- 散列表的键：$`g`$ 个 `[26]int`，$`O(g|\Sigma|)`$。键的大小与字符串长度无关，这一点与排序键不同。
- 散列表的列表：共 $`n`$ 个字符串头，$`O(n)`$，直接作为输出；字符串内容与输入共享，没有复制。
- `cnt`：$`O(|\Sigma|)`$。
- `res`：$`O(g)`$。

总空间 $`O(n + g|\Sigma|) \le O(n|\Sigma|)`$。不计输出时额外空间为 $`O(g|\Sigma|)`$，最坏 $`O(n|\Sigma|)`$。

## 5. 思维难点（Learning Notes）

### 难点一：为什么不把计数拼成字符串作键？

在不支持数组作键的语言里，常见做法是把 26 个计数拼成字符串。直接拼接数字会出错。

**理解过程**

把计数按顺序写成十进制再拼起来时，`"aaaaaaaaaaa"`（11 个 `a`）的计数是 $`(11, 0, 0, \ldots)`$，拼成 `"110"` 后跟 24 个 `0`；`"abbbbbbbbbb"`（1 个 `a`、10 个 `b`）的计数是 $`(1, 10, 0, \ldots)`$，拼出来同样是 `"110"` 后跟 24 个 `0`。两个字符串不是异位词，却得到相同的键，违反了完全不变量的“$`f(s) = f(t) \Rightarrow s \sim t`$”方向。要么在数字之间加分隔符（例如 `"11#0#0..."`），要么像本解法一样直接用定长数组作键。测试中的 `Letter counts that collide if concatenated without separators` 用例就是这一对字符串。

**可迁移思维：** 把多个字段编码成一个键时，编码必须是**单射**：不同的字段组合要得到不同的键。变长字段直接拼接通常不是单射，要加分隔符、写长度前缀或改用定长表示。

### 难点二：计数键一定比排序键好吗？

计数键的渐近时间更低，但它依赖字母表小而固定。

**理解过程**

计数键每个字符串都要付出 $`O(|\Sigma|)`$ 的清零、散列和比较代价，键也占 $`|\Sigma|`$ 个整数。本题 $`|\Sigma| = 26`$，这是常数；但如果字符串可以包含任意 Unicode 字符，$`|\Sigma|`$ 会大到无法用数组计数，这时要么改用 `map[rune]int` 计数再规范化，要么回到排序键，排序键的代价只与字符串长度有关。

**可迁移思维：** 直接寻址（用数组按值计数）适合值域小的情形；值域大时它的空间和清零代价会超过收益。选规范形式时，要同时看字符串长度 $`k`$ 和字母表大小 $`|\Sigma|`$。

## 6. 可迁移知识（Key Takeaways）

本题总结出以下可复用的方法：

1. **Count Vector as Canonical Form（计数向量作规范形式）**：在本题中，26 个字母的计数向量是每个异位词类的唯一代表。适用于只关心多重集、不关心顺序的比较，例如判断重排、滑动窗口中的异位词匹配；限制是字母表必须小而固定。
2. **Direct-Address Counting（直接寻址计数）**：在本题中用 `cnt[s[i]-'a']++` 统计字母，每次 $`O(1)`$ 且没有散列冲突。适用于值域是小区间的计数；值域大或稀疏时改用散列表计数。
3. **Injective Key Encoding（单射的键编码）**：在本题中用定长数组作键，避免拼接字符串时不同计数撞成同一个键。适用于把多个字段合成一个散列键的任何场景；成立条件是不同的字段组合编码后必须不同。
4. **Group by Key（按键分组）**：与[排序键解法](../sorted-key/summary.zh-CN.md#6-可迁移知识key-takeaways)相同，正确性只依赖键是完全不变量，与键的具体形式无关。
